## 🧪 テストの種類

### 1. 機能テスト

[test-matrix.md](./test-matrix.md) を使用して、各機能の動作確認を行います。

**テスト対象:**

- 認証機能
- ルーティン管理（CRUD、表示、通知）
- ライフログ機能（家計簿、ジャーナル、食事記録等）
- 生産性機能（ポモドーロ、作業記録）
- クラウド同期
- データ管理

### 2. 自動テスト

```bash
# ユニットテスト実行
npm test

# カバレッジ付きテスト
npm run test:ci

# ウォッチモード
npm run test:watch
```

### 3. E2Eテスト

Playwrightで、実際にブラウザを操作する主要フローを検証します（`e2e/`配下）。

```bash
# E2Eテスト実行（Playwrightがdevサーバーを自動起動）
npm run test:e2e

# UIモードで実行（ブラウザ操作の様子を確認しながらデバッグ）
npm run test:e2e:ui
```

**カバーしているフロー**

| ファイル | 内容 |
| --- | --- |
| `e2e/routine-creation.spec.ts` | 匿名ログイン → ルーティン作成 → 一覧表示 |
| `e2e/todo-list.spec.ts` | Todoリスト作成 → Todo追加 → 完了操作と進捗更新 |
| `e2e/settings-persistence.spec.ts` | 設定変更 → リロード後も値が保持される |
| `e2e/menu-navigation.spec.ts` | ハンバーガーメニューからの各ページ遷移 |

ログインやメニュー遷移など共通の操作は `e2e/helpers.ts` にまとめています。

- Firebase未設定でもlocalhostのローカル疑似ログイン（`NEXT_PUBLIC_ENABLE_LOCAL_AUTH`）で動作するため、Firebase認証情報の設定は不要です。
- CIでは`chromium`のみ実行しています。

### 4. ビルドテスト

```bash
# 型チェック
npm run typecheck

# Lintチェック
npm run lint

# ビルドテスト
npm run build
```

## 📋 テストマトリクスの使い方

### ステータス凡例

| ステータス | 意味                         |
| ---------- | ---------------------------- |
| ✅         | 実装済み                     |
| 🔶         | BETA（開発途中・不安定）     |
| 🚧         | 開発予定（未実装・実装途中） |
| ⬜         | 未確認                       |

### チェック手順

1. [test-matrix.md](./test-matrix.md) を開く
2. テスト対象の機能を選択
3. PCとスマホで動作確認
4. ステータス欄にチェック結果を記入

### 注意が必要な機能

- **🔶 通知機能**: BETA版・不安定
- **🚧 ドラッグ&ドロップ**: 開発途中

## 🔍 テスト観点

### 基本動作

- [ ] 各機能が正常に動作するか
- [ ] エラーハンドリングが適切か
- [ ] ローディング表示が適切か

### データ永続化

- [ ] LocalStorageに正しく保存されるか
- [ ] ページリロード後もデータが保持されるか
- [ ] Firestore同期が正常に動作するか

### UI/UX

- [ ] レスポンシブデザインが機能するか
- [ ] アクセシビリティが確保されているか
- [ ] エラーメッセージが分かりやすいか

### ブラウザ互換性

- [ ] Chrome（最新版）
- [ ] Safari（最新版）
- [ ] Firefox（最新版）
- [ ] モバイルブラウザ（iOS Safari、Android Chrome）
