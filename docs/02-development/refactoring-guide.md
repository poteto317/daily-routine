# Reactコンポーネント・リファクタリング・ガイド

## 目標: 「1ファイル80行以内」のクリーンなコンポーネント設計

このドキュメントは、肥大化したReactコンポーネントを分解し、保守性と可読性を最大化するための全手順を網羅したものです。

---

## 🚀 リファクタリングの8ステップ

### 1. 安全性の確保（テストの準備）

リファクタリングの鉄則は「挙動を変えないこと」です。

- **現状の動作確認:** 既存のコンポーネントが正常に動作しているか再確認します。
- **ユニットテストの作成:** 可能であれば、React Testing Library等で現在の挙動を保証するテストを書きます。これが後の「答え合わせ」になります。

### 2. 現状分析（関心の分離）

コードを以下の4つの要素に分類し、どこに何が書かれているかを把握します。

1. **定数・設定:** 固定文字列、APIエンドポイント、設定オブジェクト。
2. **純粋なロジック:** データの加工、計算、バリデーション（Reactの状態に依存しないもの）。
3. **状態管理・副作用:** `useState`, `useEffect`, APIコール等の「動的な振る舞い」。
4. **UI構造:** JSX（HTML構造とコンポーネントの配置）。

### 3. 低コストな抽出（定数とユーティリティ）

まずは「コンポーネントの外に出せるもの」を移動します。

- **定数の外部出し:** `const OPTIONS = [...]` などをファイル最上部、または `constants.ts` へ移動。
- **純粋関数の抽出:** 引数を受け取って値を返すだけの関数をコンポーネントの外へ。これにより、コンポーネント内は「呼び出しの1行」のみになります。

### 4. ロジックの外部出し（Custom Hooks化）

最も効果的なステップです。

- **フックの作成:** `useSomething.ts` を作成し、`useState` や `useEffect` などのロジックを丸ごと移行します。
- **インターフェース定義:** フックが返すべき「状態」と「操作関数」を整理して `return` します。
- **本体のスリム化:** コンポーネント側は `const { data, handleSelect } = useSomething();` と呼び出すだけの状態にします。

### 5. UIの分解（コンポーネントの分割）

JSXの肥大化を防ぎます。

- **ループの抽出:** `map()` 内の複雑なJSXは、即座に `ItemCard` 等の別コンポーネントに切り出します。
- **論理ブロックの分割:** ヘッダー、フォーム、リストなどの意味のある単位でコンポーネントを分けます。
- **ガード句（Early Return）の活用:** ローディングやエラー時の表示を関数の先頭で返すことで、メインロジックのネストを浅くします。

### 6. スタイルの分離

スタイル定義がコードの視認性を下げている場合、物理的に分離します。

- **別ファイル化:** `Component.styles.ts` 等を作成し、CSS-in-JSの定義を移動します。
- **構造の明確化:** 本体ファイル (`index.tsx`) には「構造」だけが残るようにします。

### 7. 型定義の整理（TypeScript）

- **Interfaceの抽出:** 長いPropsやStateの型定義を `types.ts` またはファイル末尾に移動します。
- **型推論の活用:** 自明な初期値を持つ場合は明示的な型指定を削り、記述を簡潔にします。

### 8. 仕上げと検証

- **コードの掃除:** 未使用の `import` を削除し、Prettier等で整形します。
- **動作検証:** 手順1で用意したテストをパスすることを確認します。
- **セルフレビュー:** 「80行以内で、かつパッと見て役割が理解できるか？」を最終確認します。

## 📏 行数ガイドライン

- **理想**: 1ファイル80行以内
- **許容**: 120行程度まで
- それ以上の場合は、このガイドに従ってリファクタリングを検討してください。

行数はきっかけであり、分割の理由そのものではありません。次のものは、長くても行数だけを理由に分割しません。

- 処理を持たず、分解代入と props の受け渡しだけをしているコンポーネント（分割しても props の中継が増えるだけになります）
- 複数の ref を共有する 1 つの状態機械になっているフック

分割するのは、同じ形の DOM の繰り返しや、独立して読める処理があるものです。

## 🌍 国際化対応（このプロジェクトの方針）

### テキスト定数は `locales/ja.json` に集約

```typescript
// ❌ 悪い例: ハードコード
const title = "ルーティン管理";
const message = "削除しますか？";

// ✅ 良い例: locales/ja.json から読み込み
import texts from "./locales/ja.json";
const title = texts.page.title;
const message = texts.page.confirmDelete;
```

### ビジネスロジックは `helpers.ts` に分離

```typescript
// helpers.ts
export function calculateProgress(completed: number, total: number): number {
  return total > 0 ? Math.round((completed / total) * 100) : 0;
}

// Component.tsx
import { calculateProgress } from "./helpers";
const progress = calculateProgress(completedCount, totalCount);
```

### コメントは日本語で記述

```typescript
/**
 * ルーティンの完了状態を切り替える
 * @param routineId - ルーティンID
 */
function toggleRoutine(routineId: string) {
  // 完了状態を反転
  // ...
}
```
