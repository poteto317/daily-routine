# 通知配信ログ修正の実装計画

[設計書](../specs/2026-11-22-notification-log-privacy-design.md) に従う。レビュー知見 L-017、L-029、L-031 を反映する。

1. 成功、送信済み、FCM 送信失敗、履歴の保存失敗、履歴の確認失敗のテストを書く。固定の結果・ハッシュの照合・呼び出し回数を検証する。SDK 例外に合成のルーティン名とトークンを入れて、元例外や cause が出力先へ渡らないことを確認する。
2. `sendRoutineNotification` で既存の重複確認キーをハッシュする。通知と Firestore 操作は保持し、ログを固定の結果と診断用 ID に置き換える。履歴の確認失敗は安全な例外として伝える。参照がなくなったトークンの省略表示ヘルパーとそのテストを削除し、Functions の README のファイル一覧を更新する。
3. 通知のテスト、全体の検証コマンド、Functions とアプリのビルドを実行する。実装とテスト、設計・計画を責務ごとにコミットする。
