# 通知同期の認証と保存先

カード #21 の目的は、未認証の通知同期を拒否し、本人の登録先だけを更新できるようにすること。個人の同期データを保存する `users` は、通知の受付・配信処理から参照しない。

## API と保存先

- `POST /syncRoutines` は Firebase Authentication の ID トークンを Bearer ヘッダーで受け取り、Admin SDK で検証して UID を確定する。欠落、期限切れ、検証失敗は 401。CORS の `OPTIONS` は認証前に処理する。
- 本文は FCM トークンとルーティン配列。保存・配信に必要な形式を検証し、通知に使う項目だけを保存する。空配列は許可する。ユーザー ID を指定する欄は設けない。
- `notificationSubscriptions/{sha256(FCMトークン)}` に UID、FCM トークン、配信用ルーティン、更新時刻を保存する。トランザクションで登録済み UID を確認し、別 UID にひも付く登録は専用コード `subscription-owner-mismatch` 付きの 403。複数端末は端末ごとに登録できる。初回登録の対象はブラウザーが取得した FCM トークンであり、初回登録は FCM トークンを持つことを前提とし、登録済みの所有者は変更できない。トークンは秘密として扱う。クライアントの Firestore 直接アクセスは既存の既定拒否が適用される。
- 通知スケジューラーは専用コレクションだけを読み取る。旧登録は所有者を検証できる記録がないため移し替えない。旧ドキュメントは削除せず、既存利用者は更新後のアプリを開いて再登録する。

## ブラウザーと公開

- Firebase Auth の利用者とローカルのユーザースコープが一致する場合に同期する。認証状態が確定したときは、認証イベントに伴う旧データのコピーより前に、その UID 固有のキーから読み取れたルーティンだけを同期し、未取得または破損した保存値を空配列として送らない。旧データをコピーしたキーは記録し、再ログイン後にも起動時の自動送信から除外する。利用者が編集した内容の同期は許可する。明示的に空にした保存は空配列を送る。認証ガード配下の画面を UID ごとに作り直す。通知が未許可の場合は同期しない。
- 同じページの同期は順に送信し、スナップショットの取得・保存時点の UID と、Firebase セッションを一緒に保持する。キュー実行時、送信直前、再試行前に照合する。専用の 403 コードに一致する場合、同じ Firebase User オブジェクトとローカルスコープでのみブラウザーの FCM トークンを更新して一度再試行する。HTTPS を使い、明示のローカル Emulator 用ループバックのみ HTTP を許可する。リダイレクトには追従しない。
- `syncRoutines`、`checkNotifications`、Web アプリの順に公開する。問題が起きた場合も認証なしの受付は再公開しない。切り替え中と既存利用者がアプリを開くまで、クラウドからの通知が一時的に止まる。個人同期のデータ移行は不要。
