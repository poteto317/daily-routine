# 週間目標・ストリーク機能 設計

## 目的

各ルーティングループに「週に何回実行するか」という目標を設定し、週単位の達成状況と継続週数を確認できるようにする。毎日実行する習慣だけでなく、週に数回行う柔軟な習慣を継続しやすくする。

## スコープ

- ルーティン作成・編集時の週間目標設定
- ホーム画面での週間目標バッジ表示
- 統計ページ週次表示での目標進捗、残り回数、現在ストリーク、最長ストリーク表示
- 週間目標を含む履歴スナップショット
- 既存のローカル保存、Firestore同期、スナップショット、JSON入出力との互換性
- JSTを基準とする週次集計

ダッシュボード、新しい通知、アニメーション、日単位のストリークは対象外とする。目標達成時は色とアイコンによる軽い強調だけを行う。

## 採用アプローチ

週間目標は `Routine` にオプショナルなメタデータとして保持する。同一の論理ルーティンを表す `groupId` の全メンバーに同じ値を複製する。

別ストレージに正規化する案もあるが、同期対象追加、削除時の参照整合性、インポート・エクスポートの変更範囲が大きい。既存の `Routine[]` を同期・復元する仕組みを利用できることを優先し、ルーティン本体へ含める。

## データモデル

```ts
export interface WeeklyGoal {
  targetPerWeek: number;
  startedAt: string;
}

export interface Routine {
  // 既存フィールド
  weeklyGoal?: WeeklyGoal;
}
```

- `targetPerWeek` は1〜7の整数とする。
- `startedAt` は目標を新規設定した時刻、または目標回数を変更した時刻のISO文字列とする。
- 目標回数を変更した場合は異なる達成条件になるため、ストリークを新しく開始する。
- 目標を変更せずほかのフィールドだけ編集した場合は `startedAt` を保持する。
- 目標を解除した場合は現在の `Routine` から `weeklyGoal` を除去する。過去の履歴スナップショットは保持する。
- 同一 `groupId` の全ルーティンに同じ `weeklyGoal` を保存する。編集時は週間目標だけをグループ全体へ反映し、タイトルや時刻など既存フィールドの更新範囲は変更しない。

`DailyHistory.routineSnapshots` には以下を追加する。

```ts
{
  // 既存フィールド
  groupId?: string;
  weeklyGoal?: WeeklyGoal;
}
```

既存履歴では両フィールドが欠けるため、週間目標なしとして安全に読み込む。

## 集計ルール

### 論理ルーティンの識別

- `groupId` がある場合は `groupId` を目標IDとして使用する。
- レガシーデータなど `groupId` がない場合はルーティンの `id` を使用する。
- 同じ日に同一目標IDの完了が複数あっても1回として数える。

### 週の境界

- アプリ既存の統計と同じく月曜日開始・日曜日終了とする。
- 日付判定はAsia/Tokyoのカレンダー日を使用する。
- `startedAt` が属する週は、その週の月曜日からの完了履歴を集計対象にできる。目標設定前の同週内の完了も初週の進捗に含める。

### 週の達成

- 対象週の異なる達成日数が `targetPerWeek` 以上なら達成週とする。
- 目標設定前の週は判定対象外とする。
- 目標設定後に履歴が存在しない終了済み週は0回の未達週とする。
- 選択した過去週では、その週の履歴スナップショットに保存された目標条件を優先する。
- 現在週では現在のルーティン設定を含め、まだ完了履歴のない目標も0回として表示する。
- 削除済みルーティンは、履歴スナップショットが残る過去週では表示・集計できる。現在週の一覧には表示しない。

### ストリーク

- 現在ストリークは、基準週から過去へ遡った連続達成週数とする。
- 基準週が現在進行中かつ未達の場合、その週はストリークを加算しないが、直前までのストリークも切断しない。
- 終了済みの未達週があればそこで現在ストリークは終了する。
- 最長ストリークは `startedAt` の週以降に存在する最長の連続達成週数とする。
- 目標値変更後は新しい `startedAt` 以降だけを対象にする。

## UI設計

### ルーティンフォーム

- 任意項目として「週間目標」を追加する。
- 数値入力で1〜7回を受け付け、空欄は目標なしとする。
- 範囲外、小数、数値でない値は保存不可とし、入力欄付近に説明を表示する。
- 新規保存時に `startedAt` を設定する。
- 編集時は既存値と比較し、目標値が変わった場合だけ `startedAt` を更新する。

### ホーム画面

- 週間目標があるルーティンカードへ `週3回` のようなバッジを表示する。
- 同じグループの曜日別カードには同じバッジを表示する。
- ホーム画面では集計処理を増やさず、進捗やストリークは統計ページへ集約する。

### 統計ページ

- 既存の週次表示に「週間目標」パネルを追加する。
- 目標ごとにタイトル、達成数/目標数、残り回数、進捗バー、現在ストリーク、最長ストリークを表示する。
- 達成済みは緑色とチェックアイコンで強調する。
- 未設定または対象目標がない週は空状態メッセージを表示する。
- 期間移動時は選択週の条件と履歴を使って再集計する。

## コンポーネントと責務

- ルーティンフォームのstate/model: 入力値、検証、`WeeklyGoal` の生成と保持
- ルーティンmutation model: 同一グループへの週間目標伝播
- 履歴snapshot builder: `groupId` と週間目標の保存
- 週間目標statistics module: 日別履歴のグループ化、週達成、現在・最長ストリークの純粋計算
- statistics hook: 選択週、現在ルーティン、全履歴から表示モデルを生成
- weekly goals panel: 表示だけを担当し、集計ロジックを持たない

計算ロジックはReactコンポーネントやLocalStorageアクセスから分離し、JST日付を明示的に受け取る純粋関数を中心にする。

## 同期と互換性

- `Routine[]` と `DailyHistory` は既存の同期payloadに含まれるため、新しいトップレベル同期キーは追加しない。
- オプショナルフィールドとして追加し、旧端末・旧エクスポートを読み込めるようにする。
- 正規化処理が未知または欠落フィールドを破壊しないことを同期テストで確認する。
- JSON入出力が既存の同期payloadまたはストレージ値を利用している箇所を確認し、週間目標が欠落しないことをテストする。
- `targetPerWeek` が壊れているデータは目標なしとして集計し、画面を落とさない。

## エラー処理

- フォームでは不正な目標値を保存前に拒否する。
- 読み込み時の不正値は集計対象外とし、既存のルーティン表示自体は継続する。
- 欠落した履歴、空の週、削除済みルーティンを正常系として扱う。
- 日付文字列が不正な目標はストリーク対象外とする。

## テスト戦略

1. データモデルとフォーム
   - 空欄、1、7、0、8、小数、非数値
   - 新規目標の `startedAt`
   - 目標値維持時の `startedAt` 保持
   - 変更時の `startedAt` 更新
   - グループ全体への目標伝播
2. 履歴
   - snapshotへの `groupId` と週間目標保存
   - 旧snapshotの読み込み
3. 集計
   - 月曜開始・日曜終了とJST境界
   - 同日・同一グループの重複除外
   - 達成、未達、残り回数
   - 進行中の現在週が未達でも既存ストリークを維持
   - 終了済み未達週でストリーク終了
   - 目標変更後の再スタート
   - 現在・最長ストリーク
   - 削除済みルーティンの過去集計
4. UI
   - フォーム入力とバリデーション
   - ルーティンカードのバッジ
   - 週間目標パネルの空・進行中・達成状態
   - 週移動時の再表示
5. 永続化
   - Firestoreアップロード・ダウンロード
   - 同期スナップショット復元
   - JSONエクスポート・インポート
6. 全体検証
   - 対象Jestテスト
   - 関連Playwrightシナリオ
   - `npm run verify`

## 完了条件

- ユーザーが各ルーティングループへ週1〜7回の目標を設定・変更・解除できる。
- ホーム画面で目標設定を識別できる。
- 統計ページで選択週の進捗、残り回数、現在・最長ストリークを確認できる。
- 進行中週、未達週、目標変更、削除済みルーティン、旧データを定義どおり扱う。
- 週間目標と履歴が既存の同期・復元・入出力で失われない。
- 対象テスト、E2E、`npm run verify` が成功する。
