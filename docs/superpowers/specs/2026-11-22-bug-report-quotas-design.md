# 不具合報告の処理上限

スクラムかんばんへの起票と AI 整形を実行する前に、Firestore のサーバー側トランザクションで処理枠と期限付きロックを確保する。枠は UTC の暦日（日本時間 09:00 切り替え）ごとに、起票先プロジェクトと、そのプロジェクト内の報告者の両方に適用する。

- 日次上限の初期値は利用者 5 回、プロジェクト全体 50 回。Firebase パラメータで変更でき、0 を指定すると対象の処理枠を停止する。
- トランザクションは報告の現在の状態を確認し、受理する場合に両方のカウンターとロックをまとめて更新する。処理済み・有効なロックの重複イベントは枠を消費しない。期限切れロックの再取得は新しい処理として枠を消費する。
- 上限到達後の報告は `status: error` と `errorCode: quota_exceeded` で記録する。画像取得・AI 整形・起票は実行せず、翌日も再処理しない。外部処理の失敗で消費した枠を戻さない。
- 枠は処理権の確保を試みた時点の UTC 日付に計上する。既定のプロジェクト日次枠で受理される処理は最大 50 回。既存の処理では 1 回につき起票用の POST を最大 1 回、AI API を画像なし再試行込みで最大 2 回呼び出す。
- カウンターは既存の Firestore ルールでクライアントから読み書きできない。報告の受付方法と読み取り権限は従来どおり。カウンターや設定が異常な場合は外部処理へ進まない。
